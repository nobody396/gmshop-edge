# 客服离开回复

只处理后台配置的「老实人AI客服中心」关联的 Web／Telegram 客户会话。
不处理个人账号私聊、公开交流群或通知频道的普通消息，不接管 Chat Automation。
复用现有 webhook、客服话题及 Web 加密回复链路；没有新 Bot、轮询器、定时器或 AI 调用。

## 默认关闭，手动控制

在客服中心由已授权的真人管理员发送：

- `/away status`：查看状态和指南链接，不更改设置。
- `/away guide HTTPS链接`：登记选购指南链接，同时关闭离开回复。链接必须属于
  `laoshirenvip.com`、`cn.laoshirenvip.com` 或 `shop.laoshirenai.com`，不允许账号密码、非标准端口或 HTTP。
- `/away on`：开启一轮离开回复。没有指南链接时拒绝开启。
- `/away off`：关闭，不影响人工客服回复和原有消息转发。

重复 `/away on` 不会开始新一轮；关闭后再开启才会开始新一轮。
更换指南链接后需明确再次开启。命令不会因私人聊天、其他群、转发内容或 Bot 消息而执行。
上线前须确认指南已经发布且链接可访问；代码只校验链接格式和域名，不伪造已上线地址。

## 触发与文案

开启之后，只在客户成功提交的新消息／附件到达现有客服会话时回复；不扫描历史，不补发旧消息。
延迟到达且时间早于本轮开启的 Telegram 消息不触发提示（按 Telegram 秒级时间判断）。
每轮开启，每个会话最多一次；并发、重复消息和结果不确定的请求不会重复发送。
关闭阻止新的提示；已经发出的消息或网络中正在发送的请求不能撤回。

中文 Web 客户文案：

> 老板，我这会儿不在，有问题先留言哈
> 不知道怎么选购的，打开下面的首页，点「开始选择」看选购指南
> https://laoshirenvip.com/#self-service-recharge
> 消息看到了都会回复，回复后也会发邮件提醒你

Telegram 客服会话不显示邮件承诺。Web 会话创建时已要求客户登记邮箱；Web／Telegram
分别使用客户已选语言，支持 zh-CN 和 en-US，不跟随员工语言。
提示会镜像到对应客服话题，便于员工查看；Web 客户能在自己的原会话看到同一条加密保存的回复。
失败只记录不含正文的事件及会话标识，不影响已成功收到的客户消息，也不盲目重试提示。

## 邮件保持人工触发

离开提示不会自动发邮件、排邮件任务、启动延迟检测或触发已有邮件按钮。
Web 回复用 `is_away_reply` 标记来源，邮件按钮只接受近期真人回复，不能把自动提示当真人回复。
实际人工提醒仍走现有授权、发送域名／provider 校验和去重流程；API 接受不代表收件箱已收到。

## 实现与验证

- 设置复用 `system_settings` 的 `telegram.support.away_mode`，同一对象保存开关、轮次、开启时间、指南和客服群。
- 单次提示的原子占位复用 `replay_receipts` 的 `telegram_support_away` 命名空间。
  当前开启轮次的记录不被普通 90 天清理删除，避免长期开启后再次提示。
- `0021_support_away_reply_source.sql` 只为已有 Web 回复加来源标记，不重写初始化迁移。
- 状态变更与管理员标识通过现有 `audit_logs` 记录；没有通用代理、配置框架或业务动作权限扩张。

```bash
bun run test:support-away
```

测试用临时 SQLite、真实客服公共接口及模拟 Telegram SDK 网络边界，不联系真实客户，不发真实邮件。
发布目标使用首页定位链接 `https://laoshirenvip.com/#self-service-recharge`；到首页点击「开始选择」即可打开指南，无需单独指南页。上线与开启是两件事；登记指南不会开启离开回复。

网页消息中的商城 HTTPS 指南链接可点击，并在新标签页打开，保留原客服会话；外部域名和恶意 HTML 仍显示为纯文本。
