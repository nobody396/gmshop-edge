# Independent invoice entry

VIP 发票申请留在本站 `/invoice`，导航和订单入口不跨站。页面利用现有 CORS 策略调用统一公开开票 API，明确不携带 Cookie 或身份凭证。VIP 无订单申请保留本站来源，付款后返回 laoshirenvip.com。lsrai.shop 保留独立页面，不新增转发代理、数据库、身份系统或通知流水线。

## 提交失败处理

先检查 HTTP 和业务状态，再解析成功发票字段。业务失败可能返回 HTTP 200、非零 status_code，以及只含 request_id 的 data 对象；应显示业务错误而非 Zod 内部报告。异常成功响应显示本地化通用错误。创建失败时可能已存在待付款申请：GMShop 重试必须核对相同开票资料，复用原申请编号及金额，且不能覆盖已到账回调。

## 全费用开票与金额展示

订单金额是已付基数，不是最终票面。后端统一反算：票面 = 基数 + 本次补付；补付 = 票面 × 3%（到分）+ 可选截图费 5 元 + 补付渠道费（只对服务费和截图费计费，到分）。钱包渠道费为 0；具体费率来自后端，前端不独立算钱。670 元基数、4% 渠道费时，无截图票面为 691.58 元/补付 21.58 元；有截图票面为 696.95 元/补付 26.95 元。

预览和付款状态均突出展示「最终发票票面金额」并单列「本次需补付」。前端仅接受 `fees_included: true` 的新规则预览；原始基数从 `invoice_base_amount` 回填，不能把最终票面当基数再次加费。历史状态照实展示保存金额，不自动重算已付款申请。须先上线统一开票后端及其基数列迁移，再上线前端；本次实现不执行部署、支付、开票或通知。
