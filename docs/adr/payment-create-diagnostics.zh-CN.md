# 支付建单失败诊断

[English](payment-create-diagnostics.md)

订单页的二维码由付款链接本地生成，不是远程图片下载。原代码把支付通道拒单、
异常响应等情况合并，再统一落成 `provider_create_failed`；首次结账为了允许重试
会吞掉异常，因此具体原因丢失。

本次仅修复诊断：区分 HTTP、网络、超时、JSON/结构错误、明确拒单、付款链接缺失
或无效。通过已有 `audit_logs` 原子记录 `payment.creation_failed`，关联支付尝试，
保留耗时、IP 类型、HTTP 状态及限长脱敏的通道错误码和说明；不保存密钥、签名、
原始响应、付款链接、客户 IP 或邮箱。抛回页面的错误不携带诊断对象。

不新增表、队列、自动重试、备用支付或付款状态流程。幂等重放不得重复调用通道
或重复写审计；失败回写不得把已成功的支付尝试改回失败。超时不等于通道未建单，
恢复之前先查原商户单号，不绕过风控。

2026-10-09 的 4 笔 ¥125 订单有 7 次失败，均为同一联系人的订单。通道只读查询
均返回订单不存在，成功订单对照查询匹配。已登录后台同样没有这些订单，操作日志
只包含账号操作，当前黑名单为空。旧记录无法还原当时的拒绝响应，因此本次修复
不能被宣称为客户支付故障已恢复；部署后需要一次真实的客户手动重试来取得证据。

验证使用模拟通道响应与临时 Miniflare D1，覆盖原因保留、脱敏、失败无链接、
幂等及响应/网络异常分类，不创建真实支付单。
